# План ручной проверки комплекса на STM32F3DISCOVERY

Цель — убедиться, что прошивка (`firmware/`), десктоп (`labbench`), USB-CDC связь,
АЦП и DSP-вкладки работают «в целом» на реальной плате.

Все утверждения о железе — из официальных источников (UM1570, DS9866, RM0316).
Ограничение входа АЦП: **0 … 3.3 В относительно GND**, подача отрицательного
напряжения или > 3.3 В запрещена (ADC12 без делителя).

## Полезные факты для прогона

| Что | Факт |
|-----|------|
| USB устройства | CN1 = ST-LINK (`0483:3748`), CN2 = USB USER (PA12/PA11) — CDC-ACM |
| Вход в бутлоадер | BOOT0=1 через **SB19** + RESET (**B2**) — появится `0483:df11` |
| Heartbeat | **LD4 (синий) = PE8**, мигает ~1 Гц в прошивке при работающем USB |
| Кнопка B1 | на **PA0** (канал A1): в покое ~3.3 В, при нажатии ~0 В |
| Каналы LCR | используются ch0=PA0 (v) и ch1=PA1 (i) |
| Канал Transient | ch2=PA2 (step-ответ) |
| Частота f_s | приходит от платы пакетом `A4` (не из таблиц) |
| Тестовый генератор | DAC1_OUT1 = **PA4 (P1-16)**, 1 кГц; формы DC/синус/треугольник/меандр, амплитуда 1..8 |
| LED-индикация | LD4=heartbeat, LD5=USB, LD6=данные, LD7=генератор, LD10=тревога |

## Этап 0 — сборка и готовность софта

- [ ] `firmware`: `cargo build --release` — 0 ошибок/предупреждений.
- [ ] `desktop`: `cargo build --release` и `cargo test` (11 тестов зелёные).
- [ ] Установлены `arm-none-eabi-objcopy`, `dfu-util`; udev-правила
      (`99-stm32.rules`) скопированы в `/etc/udev/rules.d/`, перезагружены
      (`sudo udevadm control --reload-rules && sudo udevadm trigger`).
- [ ] `labbench --simulate` запускается: 4 вкладки, синус на Осциллографе.

## Этап 1 — прошивка и загрузка приложения

1. Замкнуть **SB19** (BOOT0→1), нажать **RESET**.
2. Проверить: `lsusb` показывает `0483:df11`, `dmesg` — «STM32 in DFU mode».
3. Выполнить `./firmware/flash.sh` — dfu-util шьёт и делает «leave».
4. Разомкнуть **SB19**, нажать **RESET**.
5. Критерий: `lsusb` показывает `0483:...` («STM32F3 LabBench», VID 0xc0de);
   **LD4 мигает**; после подключения кабеля в **CN2** появляется `/dev/ttyACM0`
   (проверить `dmesg`).

## Этап 2 — связь USB-CDC

6. Запустить `./target/release/labbench --port /dev/ttyACM0`.
7. Критерий: в строке статуса «подключено: /dev/ttyACM0»; в шапке вкладки
   «Осциллограф» появилось «fs = … Гц» (пришло от платы `A4`, ~0.5 с) и fps > 0.
8. Убедиться, что нет роста «lost …» без нагрузки (потери кадров на паузе близки к 0).

## Этап 3 — проверка каналов АЦП (разметка входов)

Раздача карты каналов (канал → пин → контакт P1):

| Канал | Пин | P1 | Проверка |
|------:|-----|----|----------|
| 1 | PA0 | P1-12 | **кнопка B1**: нажать — трасса уходит от ~«+1» к «−1» |
| 2 | PA1 | P1-5  | подать 1 кГц синус → трасса «дышит» на этом канале |
| 3 | PA2 | P1-14 | то же; затем используется для Transient |
| 4 | PA3 | P1-7  | то же |
| 5 | PF4 | P1-9  | то же |
| 6 | PC0 | P1-6  | то же |
| 7 | PC1 | P1-1  | то же |
| 8 | PC2 | P1-8  | то же |
| 9 | PC3 | P1-3  | то же |
| 10| PF2 | P1-10 | то же |

Процедура на канал: подать **постоянный** уровень ~1.65 В (или 3.3 В) через
1 кОм на нужный пин (общий GND) и убедиться, что именно эта трасса меняет
уровень, а соседние — нет. Затем сигнал снять.

Критерий: каждой трассе на экране соответствует свой пин, ни один пин не
«раздваивается».

## Этап 4 — осциллограф, частота, потеря кадров

9. Подать наследник: синус 1 кГц, 0.1 … 3.3 В на PA1 из функционального
   генератора (DC-coupled!, Vpp ≤ 3.3 В).
10. Критерий: на Осциллографе видна синусоида (~1 период при 1 мс/дел),
    амплитуда соразмерна входу.
11. «rate» влияет на шапку: `fs` уменьшается при малых rate и растёт при
    больших (fs голосование платы). При очень малых rate (0–1) допустимы
    редкие overrun-кадры — это видно по «ADC/DMA overrun» в статусе; при
    нормальном rate 3..5 их быть не должно.

## Этап 5 — спектр (FFT)

12. Тот же синус 1 кГц на PA1. Критерий: на вкладке «Спектр» пик около
    1000 Гц, шумовая подставка заметно ниже пика (≥ 20 дБ).

## Этап 6 — LCR / Z-метр (PA0, PA1)

13. Схема (ground-leg shunt; роли каналов по коду `measure_z(v, i_ch, …)`
    в `desktop/src/dsp.rs`: `v` = канал 0 = PA0, `i_ch` = канал 1 = PA1):

```
Vgen ── DUT ── nodeA ── R_sense (100 Ом) ── GND
 │                │
 PA0 = Vgen       PA1 = nodeA  (= I·R_sense, точно пропорционально току)
```

   Математика: показание комплекса `Z = Z_DUT + 100 Ом` (послед. с R_sense).
14. R-тест: `R_DUT = 4.7 кОм` → |Z| ≈ `sqrt(4700² + 100²) ≈ 4.7 кОм` (±10%).
15. C-тест: `C = 100 нФ` → `Xc = 1/(2π·5 кГц·100 нФ) ≈ 318 Ом`,
    `|Z| = sqrt(318² + 100²) ≈ 334 Ом`, знак реактивности ёмкостный
    (lcr покажет «C, Ф», значение ≈ 100 нФ). (±10%.)
16. L-тест (опционально): дроссель ~1 мГн → `XL = 2π·5 кГц·1 мГн ≈ 31 Ом`,
    `|Z| = sqrt(31² + 100²) ≈ 105 Ом`, «L, Гн».
17. Критерий: значения в пределах допуска, единицы «Гн/Ф» соответствуют
    элементу. При разомкнутом DUT показаний нет (защита от деления на 0).

## Этап 7 — Transient (PA2)

18. Квадрат 1 кГц / 0–3.3 В с генератора на **PA2 (P1-14)**, общий GND.
19. Критерий: на вкладке «Transient» отображается «Rise time 10–90%» порядка
    десятков мкс (для «штыря» фронта) и форма фронта.

## Этап 8 — повторный вход в DFU (полный цикл)

20. Проверить, что вход в бутлоадер аппаратный и предсказуемый: **SB19 замкнуть +
    RESET** → `0483:df11`; `flux` повторной прошивки проходит; **SB19 разомкнуть +
    RESET** → снова приложение, LD4 мигает, ttyACM0 доступен.

## Этап 9 — тестовый генератор (PA4) и LED-индикация

Самопроверка без внешнего генератора.

21. В окне `labbench` нажать панель «Генератор» → «Синус» (амплитуда по умолчанию
    4/8). Критерий: загорелся **LD7 (PE11)**.
22. Проводом соединить **PA4 (P1-16)** с **PA1 (P1-5)** (общий GND платы — на
    том же P1). Критерий: на Осциллографе (ch1) — синус ~1 кГц, размах
    соразмерен амплитуде; на «Спектре» пик ≈ 1000 Гц; `fs` от платы корректна.
23. Переключить формы: «Треугольник» и «Меандр» — форма сигнала на экране
    соответствует; «Выкл» — уровень среды шкалы, **LD7 гаснет**.
24. Амплитуда 1..8: размах растёт монотонно; на 8/8 меандр почти 0…3.3 В.
25. LED-индикация рабочего состояния: при подключённом порте горит **LD5 (PE10)**,
    при потоке кадров — **LD6 (PE15)**; при rate 0–1 и переполнении ADC мигает
    ~4 с **LD10 (PE13)**; **LD4 (PE8)** мигает всегда, пока прошивка жива.

## Типовые проблемы и их чтение

| Симптом | Причина / действие |
|---------|--------------------|
| `ttyACM0` не появляется | не подключён **CN2** (нужен второй кабель); udev-правила; кабель без данных |
| Программная прошивка «висит» при старте (LD4 не мигает) | HSE не готов: проверьте режим **Bypass** в `main.rs` и мост SB12 |
| Трассы на Осциллографе — все одинаковые | сигнал не снят с пина после проверки (обычно) |
| Overrun только на rate 0–1 | ожидаемо при сильном замедлении АЦП, не баг |
| Показания LCR нестабильны | плохой контакт «массы»: общий GND между генератором и платой обязателен |
